## 一、建筑区域系统（现状）

### 1.1 玩家体验目标

玩家在建筑区完成一条闭环：

```text
点建筑图标
  → 出现半透明蓝图，跟随鼠标
  → 蓝图吸附到格点，绿 / 红表示能不能放
  → 左键落位，蓝图冻结
  → 从材料面板把材料拖到蓝图上
  → 材料凑齐，点「确认建造」
  → 生成实体建筑，消耗材料，占用格子
```

取消、退出建筑区、读档都会把蓝图里已经放进去的材料退回库存；建成之后不能再通过蓝图撤回。

**刻意没做的：** 建筑旋转、玩家侧拆除 UI、触屏镜头、蓝图多选、批量建造。

### 1.2 系统边界与依赖方向

```text
                 BuildingUI（按钮转发）
                        │
BottomNavUI → GameAreaController ──→ AreaCameraDirector
                        │                    │
                        │                    └→ BuildingCameraDirector
                        ▼
                 BuildingManager ◄──── BuildingPlacement ──→ BuildingGrid
                   │        │                                   ▲
                   │        └──────────────→ BuildingGridVisualizer
                   ▼
            BuildingConstruction ──→ MaterialInventory
                   │
                   └──→ BuildingMaterialPanel（只读 + 拖拽转发）

BuildingSaveParticipant ──→ PlacedBuildingInfo（建筑实例上的运行时信息）
```

关键约定：

- `BuildingManager` 是建筑系统的**唯一入口**，负责「选中 / 落位 / 建造 / 移除」。
- `BuildingPlacement` 只负责「屏幕坐标 → 地面点 → 吸附 → 判定」，不生成建筑。
- `BuildingGrid` 只负责格子与占用，不读输入、不画东西。
- `BuildingConstruction` 只负责「材料进蓝图 / 撤回 / 确认」，不生成建筑。
- `BuildingMaterialPanel` 只读库存、只转发拖拽，不改数值。
- 玩法系统（挖矿、商店、建造）**没有编译期引用** `Yujian.Save`；存档单向依赖玩法。

### 1.4 建造状态机

`BuildingManager` 只暴露两个相位：`Placing`（蓝图跟手）和 `Filling`（蓝图落位、等材料）。
没有蓝图时，`Phase` 恒为 `Placing`，但 `IsPlacing == false`。

| 状态 | 进入条件 | 玩家能做什么 | 离开条件 |
|---|---|---|---|
| **Idle** | 没有蓝图 | 点建筑按钮 / 点底部导航 | `SelectBuilding` |
| **Placing** | 选中了 `BuildingData`，蓝图已实例化 | 移动鼠标、左键落位、右键平移、滚轮缩放、取消 | 左键合法落位 → Filling；取消 / 切区域 → Idle |
| **Filling** | `AnchorBlueprint` 成功，`hasAnchor = true` | 拖材料进蓝图、撤回材料、确认建造、取消 | 确认建造成功 → Idle；取消 / 切区域 → Idle |
| **Built（瞬时）** | `BuildAtAnchor` 成功 | —— | 同帧回到 Idle，镜头**仍留在建造视角** |

#### 关键路径

```text
SelectBuilding(data)
  ├─ 已有蓝图 → CancelSelection()（旧蓝图材料退回）
  ├─ 校验 BlueprintPrefab / grid / FootprintCells
  ├─ Instantiate 蓝图 → 按占地世界尺寸缩放
  ├─ blueprint.Initialize(data, worldFootprint)
  └─ SetMiningSuppressed(true)    // 放置期间禁用 MiningInput

BuildingPlacement.Update（仅 Placing）
  ├─ 指针 → 地面点（数学平面，不用物理射线）
  ├─ grid.TryGetSnappedPose(...) → snappedCenter + cellRect
  ├─ blueprint.position = snappedCenter
  ├─ IsPlacementValid(...) → Grid.CanPlace + 图层/尺寸校验 + Physics 兜底
  └─ 蓝图绿/红 + 占地高亮绿/红

左键（Player/Attack）
  └─ IsPlacementValid 通过 → BuildingManager.AnchorBlueprint(snappedCenter, cellRect)

Filling
  ├─ 拖材料 → BuildingConstruction.TryPlaceMaterialAt → 扣库存 → 记入历史 → 刷新蓝图楼层
  ├─ 撤回 → 最后一块材料退回库存；没有材料时撤回蓝图本身
  └─ 确认建造 → ConfirmBuild → BuildAtAnchor(layerColors)

BuildAtAnchor
  ├─ 再 CanPlace 一次（防止落位后环境变化）
  ├─ Instantiate 实体 → 按占地缩放 → 强制放到 Building 层
  ├─ grid.Occupy(rect, instance.GetInstanceID())
  ├─ 写 PlacedBuildingInfo（建筑数据 + 占地矩形 + 楼层颜色）
  ├─ CloseBlueprint(true) → 清空材料历史（已消耗）
  └─ 回到 Idle；当前没有自动退出建造视角
```

**两条容易搞错的规则：**

1. **落位不等于建成。** 左键只把蓝图冻结，不生成实体、不写占用、不消耗材料。真正建成只走「确认建造」。
2. **退出建造视角会取消蓝图。** `BuildingCameraDirector.ExitBuildMode()` 会先调 `BuildingManager.CancelSelection()`；
   否则下一帧「有蓝图就自动进入」会把镜头又推回去。

### 1.5 网格与占地规则

#### 参数（场景当前值，已核实）

| 参数 | 当前值 | 说明 |
|---|---:|---|
| `cellSize` | 2 世界单位 | 单格边长 |
| `cellCounts` | 52 × 52 | X 对应世界 X，Y 对应世界 Z |
| `gridCenter` | `(10.21735, 0, -9.49205)` | 与海岛可建台地中心一致 |
| `autoFitToIsland` | true | 按 `IslandDefinition.BuildableCenter / BuildableHalfExtents` 重算 |
| `buildableInset` | 0 | 可建区域向内收缩距离 |
| 占地来源 | `BuildingData.footprintCells` | 风琴博物馆 2×2 格 = 4×4 世界单位 |

> 世界尺寸 = `footprintCells × cellSize`。改 `cellSize` 会同时改变**所有建筑的实际占地尺寸**，
> 不只是格子看起来变大。改之前先确认预制体的视觉尺寸。

#### 坐标与吸附

```text
origin = gridCenter - (cellCounts * cellSize) / 2

WorldToCell(p) = ( floor((p.x - origin.x) / cellSize),
                   floor((p.z - origin.z) / cellSize) )

footprintCells(footprint) = ( max(1, ceil(footprint.x / cellSize - 1e-4)),
                              max(1, ceil(footprint.y / cellSize - 1e-4)) )

n = footprintCells
u = (groundPoint.x - origin.x) / cellSize
v = (groundPoint.z - origin.z) / cellSize

cellLineX = (n.x 为奇数) ? floor(u) + 0.5 : floor(u + 0.5)
cellLineZ = (n.y 为奇数) ? floor(v) + 0.5 : floor(v + 0.5)

rectX = ceil(cellLineX - n.x / 2 - 1e-4)
rectY = ceil(cellLineZ - n.y / 2 - 1e-4)

snappedCenter = origin + (cellLineX, 0, cellLineZ) * cellSize
```

- **奇数格宽**：中心落在指针所在格的中心。
- **偶数格宽**：中心落在最近的格线交点，建筑围绕指针展开。
- 指针完全在网格外时，`TryGetSnappedPose` 返回 false；蓝图保留上一次位置并标红，不会瞬移或消失。

#### 可建区域

每个格子采样 **4 个角点 + 中心**，5 个点全部通过才算可建。
有 `IslandSettings` 时用圆角台地距离函数 `IslandMeshGenerator.CoastDistance(...) <= -buildableInset`；
缺资产时退化为 `IslandDefinition` 的矩形判断（圆角处可能允许放到沙滩边）。

#### 合法性判定顺序（`BuildingGrid.CanPlace`）

| 顺序 | 失败原因 | 枚举 | 玩家看到的提示 |
|---:|---|---|---|
| 1 | 网格未配置 | `NotConfigured` | 网格未配置 |
| 2 | 占地宽或高 ≤ 0 | `InvalidFootprint` | 占地尺寸非法 |
| 3 | 任何一格越界 | `OutOfBounds` | 超出网格范围 |
| 4 | 任何一格已占用 | `Occupied` | 格子已被占用 |
| 5 | 任何一格不在可建台地 | `NotBuildable` | 不在可建台地上 |

`BuildingPlacement.IsPlacementValid` 在网格判定之后再加两道：

1. `BuildingLayers` 必须至少勾一个层，当前场景是 `Building`（Layer 7）。
2. `Physics.OverlapBoxNonAlloc` 兜底：只拦**没有经过网格登记**的 Building 层碰撞体。
   已登记建筑被排除，否则贴边放置会因为 PhysX 的 `contactOffset` 被误判成重叠。

#### 占用表

- `bool[] occupied`，下标 = `x + y * cellCounts.x`。
- `Dictionary<int, RectInt> ownerRects`：ownerId = 建筑实例的 `GetInstanceID()`。
- 建成时 `Occupy`，拆除时 `Release`；同一 ownerId 重复登记会先释放旧记录。
- 网格运行中改变格数会清空占用表并警告，所以**网格视为静态配置**。

### 1.6 材料与建造结算

#### 需求怎么来

`BuildingData.requiredMaterials` 是唯一来源，例如「小砖 ×3」。
材料面板再展开成「红色小砖 / 蓝色小砖 / 绿色小砖」三个条目，数量为 0 也列出。

- **需求不指定颜色**：`砖块 ×3` = 任意颜色共 3 块。
- 颜色只影响建成后的楼层外观，不参与需求匹配。
- 没有需求（或需求全无效）的建筑，落位后就能直接建。

#### 放入材料的校验顺序（`CanAcceptMaterial`）

| 顺序 | 条件 | 失败文案 |
|---:|---|---|
| 1 | 当前有蓝图且处于 `Filling` | 请先把蓝图放到地面上 |
| 2 | 有选中的建筑 | 没有选中的建筑 |
| 3 | 材料非空 | 材料数据为空 |
| 4 | 建筑确实需要这种材料 | 「建筑名」不需要「材料名」 |
| 5 | 该材料还没放满 | 「建筑名」的「材料名」已经放满了 |
| 6 | 库存里有 1 个该颜色 | 原料不足，请购买 |

通过后：**先扣库存，再记历史**；扣失败就什么都不做，不会出现「账上多一块、库存没少」。

#### 撤回与退款

| 操作 | 行为 |
|---|---|
| 蓝图里有材料时点撤回 | 撤回最后放入的一块，退回库存（后进先出） |
| 蓝图里没有材料时点撤回 | 撤回建筑蓝图本身 |
| 取消蓝图 / 退出建造视角 / 切区域 | 蓝图里剩余材料**全部**退回库存 |
| 确认建造成功 | 材料视为已消耗，历史清空，不能再撤回 |
| 读档 | 丢弃当前蓝图**不退款**，再按存档里的 `blueprintRefund` 退一次，避免双倍 |

#### 确认建造

`BuildingMaterialPanel` 里「确认建造」的 `interactable = BuildingConstruction.IsSatisfied`：
材料没齐时按钮灰掉。因此 `ConfirmBuild()` 里「材料还不够」那条分支正常 UI 走不到，但代码保留给其他调用方。

### 1.7 已放置建筑

- `BuildingManager.placedBuildings` 是运行时唯一列表。
- 实体生成在 `anchoredPosition`，旋转固定 `Quaternion.identity`。
- **按占地自动缩放**：测量所有 Renderer 的 X/Z 包围盒，缩放到 `footprint × cellSize`；
  高度（Y）保持不变。粒子 / 拖尾 / 线段 Renderer 被排除，避免特效影响尺寸。
- 楼层颜色由 `BuildingLayerStack.Apply(layerColors)` 自下而上刷；层数 = 材料块数。
- 建筑实例上自动挂 `PlacedBuildingInfo`，记录 `BuildingData`、`RectInt`、颜色列表；存档只读这份信息。
- 建造 / 读档恢复都会强制把实例放到 `BuildingLayers` 的第一个层（当前 `Building`）。
- 移除走 `BuildingManager.RemoveBuilding(GameObject)`：先从列表移除、再释放占格、广播 `OnBuildingRemoved`、最后 `Destroy`。

**【风险】** 目前没有玩家侧拆除入口。任何绕过 `RemoveBuilding` 直接 `Destroy` 的路径都不会释放占用，
也不会让等级重算。当前只有读档清场和代码调用会走安全路径。

**【风险】** `PlayerLevel` 只订阅了 `OnBlueprintClosed(true)`，**没有**订阅 `OnBuildingRemoved`。
所以拆除建筑后等级不会自动下降；读档恢复后由 `BuildingSaveParticipant` 主动 `Recalculate()`。
做拆除 UI 时必须补这一处。

### 1.8 存档相关（建筑部分）

`BuildingSaveParticipant` 每座建筑写：

```text
buildingId         // BuildingData.saveId（资产 GUID）
x, y, width, height // RectInt 占地格子
layerColors[]      // 自下而上的 MaterialColor 枚举值
```

读档流程：

1. `ClearPlacedBuildings()` 移除当前所有建筑并释放占格。
2. 按 `SaveCatalog` 把 `buildingId` 解析回 `BuildingData`。
3. `RestoreBuilding(...)`：校验占地格数 → `CanPlace` → 在 `CellRectCenter(rect)` 生成 → `Occupy` → 写 `PlacedBuildingInfo`。
4. 全部恢复后 `PlayerLevel.Recalculate()`。

蓝图里已放的材料写进 `SaveData.blueprintRefund`，读档时退回库存；**蓝图本身不恢复**。

> 真实工程还没跑过 `屿见/通用模块/配置存档系统`；`BuildingData.saveId` 需要向导生成。
> 没跑向导时建筑存档会跳过该建筑并在 Console 报错。

### 1.10 想改 X 时改哪里

| 想改什么 | 改哪里 | 备注 |
|---|---|---|
| 格子大小 / 网格范围 | `BuildingGrid` Inspector | 优先不改代码；改完重跑 `Rebuild` |
| 可建边界更严格 | `buildableInset` 或 `IslandSettings` | 圆角判定来自海岛资产 |
| 加一种建筑 | 新建 `BuildingData` → 填 Prefab / 蓝图 / 占地 / 材料 → 加进 `BuildingUI.availableBuildings` → 配按钮 | 不要改 `BuildingConstruction`，它不认识具体建筑 |
| 改某建筑需要什么材料 | `BuildingData.requiredMaterials` | 颜色仍不指定 |
| 改楼层高度 / 层数表现 | `BuildingLayerStack.totalHeight` + 建筑预制体样板层 | 层数由材料数量决定 |
| 改吸附规则（奇数 / 偶数） | `BuildingGrid.TryGetSnappedPose` | 改完要同步改存档的落位假设 |
| 加建筑旋转 | `BuildingGrid.TryGetSnappedPose` + `BuildingManager.BuildAtAnchor` + 存档 schema | **会动存档版本，单独开阶段** |
| 加玩家拆除 | `BuildingManager.RemoveBuilding` + 新 UI + `PlayerLevel` 订阅 | 还要确认存档时机 |
| 改建造相机操作 | `BuildingCameraController` + Input Actions | 见第二部分 |
| 改出生点 / 父节点 | `BuildingManager` Inspector | 不用改代码 |

### 1.11 当前已知限制

- 不支持建筑旋转；所有实例 `Quaternion.identity`。
- 不支持玩家拆除 UI；`RemoveBuilding` 只有代码入口。
- 占用只在 `BuildAtAnchor` / `RestoreBuilding` 登记；绕过 Manager 的销毁不会释放。
- 网格配置视为静态；运行中改格数会清空占用。
- `Footprint` 必须和预制体视觉尺寸一致，否则会出现「看着重叠、格子却说能放」。
- 蓝图一次只能有一个；切换建筑会取消旧蓝图并退款。
- 材料需求不区分颜色。
- 建造成功后镜头停在建造视角，这是刻意设计（方便连摆），退出要玩家点「退出建造」或切区域。
- 没有触屏的建造相机操作。

- [ ] 移到已占用格 / 网格外 / 圆角台地外：蓝图与高亮变红，左键无效，Console 说明具体原因。
- [ ] 空位左键：蓝图冻结，不生成实体、不写占用；材料面板可拖料。

## 二、镜头移动系统（现状）

### 2.1 目标

三个区域各有自己的机位：

| 区域 | 机位 | 谁在管 |
|---|---|---|
| 挖矿 | 场景初始姿态 `(-20.93, 0.82, -12.9)` / `(0,0,0)` | `AreaCameraDirector` |
| 商店 | `(-23.49, 22, -23.28)` / `(45,0,0)`（推算值，非实拍） | `AreaCameraDirector` |
| 建筑 | `(10.21735, 49.15, -43.9)` / `(55,0,0)` | `BuildingCameraDirector` |

建造模式内额外支持：右键拖拽平移、滚轮缩放。**左键只负责落位，绝不复用。**

### 2.2 相机归属：三个脚本，一个门闩

同帧只能有一个脚本写 `Main Camera` 的 Transform。当前规则：

| 脚本 | 什么时候写相机 | 什么时候让位 |
|---|---|---|
| `BuildingCameraDirector` | 两个机位之间过渡（`transitioning == true`） | 过渡结束后不再写 |
| `BuildingCameraController` | `IsInBuildMode && !IsTransitioning`，在 `LateUpdate` | 非建造模式或正在过渡 |
| `AreaCameraDirector` | 非建筑区、且 `BuildingCameraDirector` 既不在建造模式也不在过渡 | 建造模式 / 过渡期间完全不写，连速度清零 |

`BuildingCameraDirector.IsInBuildMode` 和「场上有蓝图」不是一回事：

- 有蓝图 → `BuildingManager.IsPlacing == true` → 自动进入建造模式。
- 建成后蓝图消失，`IsPlacing == false`，但 `inBuildMode` 仍为 true，镜头留在建造视角。
- 只有 `ExitBuildMode()`（玩家点退出 / 切到非建筑区）才退出。

### 2.3 区域机位（`AreaCameraDirector`）

- 启动区域 `startArea = Mining`；`GameAreaController.Start()` 会补发一次 `OnAreaChanged`。
- `snapOnStart = true`：第一次应用区域时直接把相机放到位，不播过渡。
- 目标位置用 `Vector3.SmoothDamp`，最大速度 `moveSpeed = 25`，平滑时间 `smoothTime = 0.35`；
  旋转用同一时间常数的指数平滑 `1 - exp(-dt / smoothTime)`。
- 到目标后精确吸附，清零速度，避免浮点抖动。
- 参数 ≤ 0 会在 `Awake` 夹住并报警。
- 切到建筑区：本类清空目标、速度，交给 `BuildingCameraDirector.EnterBuildMode()`。
- 从建筑区切走：先 `ExitBuildMode()`（会取消蓝图并退款），再走向挖矿 / 商店机位。

**【风险 / 已知瑕疵】** 从建筑区直接切到商店区时，`ExitBuildMode` 先花 0.6 秒退回「常规机位」，
本类让位到它退完才动身，所以镜头会**先经过挖矿视角再拐向商店**。
想减轻：调小 `BuildingCameraDirector.transitionDuration`，或以后让区域切换直接请求目标机位。

### 2.4 建造机位过渡（`BuildingCameraDirector`）

| 字段 | 场景值 | 说明 |
|---|---:|---|
| `enterAutomatically` | true | 场上一有蓝图就自动进入 |
| `buildingModePosition` | `(10.21735, 49.15, -43.9)` | 建造机位 |
| `buildingModeEulerAngles` | `(55, 0, 0)` | 俯角 55° |
| `transitionDuration` | 0.6 秒 | ≤ 0 表示瞬切 |
| `transitionCurve` | EaseInOut(0,0,1,1) | 支持回弹；空曲线会退化为线性 |

规则：

- 常规机位 = `Awake` 时相机的实际姿态，退出建造时回到这里。
- 过渡起点取相机的**当前实际姿态**，不是上一次目标；中途被打断也能顺接。
- 用 `LerpUnclamped` / `SlerpUnclamped` 支持曲线回弹，结束时精确吸附。
- 组件右键菜单「把相机当前位置记录为建筑模式机位」直接把摆好的镜头存进字段，不要手敲坐标。
- 重跑阶段 3 向导会覆盖建造机位；阶段 7 向导不碰它。

### 2.5 建造模式平移 / 缩放（`BuildingCameraController`）

#### 控制模型

第一次获得控制时：

```text
焦点 focusPoint = 相机前向与网格水平面的交点
偏移 cameraOffset = 相机位置 - focusPoint
之后：平移只改 focusPoint，缩放只改 cameraOffset 的长度，旋转始终不变。
```

相机前向与地面没有交点时，退化为「相机正下方的地面点」并警告。

#### 平移

| 项 | 值 / 规则 |
|---|---|
| 触发 | 按住鼠标右键 + 指针位移 |
| 输入 | `Player/Look`（`<Pointer>/delta`），复用，不新建输入资产 |
| 灵敏度 | `panSensitivity = 1`，1 ≈ 指针下的地面跟手 |
| 方向 | 抓取地面式：鼠标向右拖，世界向右跟手，焦点向左走 |
| 垂直反转 | `invertPanY = false` |
| 边界 | 焦点夹在网格 `WorldMin/Max` 内，`edgePadding = 4` |
| 网格过小 | 宽高不足 2×padding 时直接夹到中心，避免 Min > Max |
| UI 屏蔽 | 按下时若指针在 UI 上，整个拖动过程都不平移（拖出 UI 也不突然跳） |

平移量按屏幕像素换算世界距离：

```text
透视：worldPerPixel = 2 * distance * tan(FOV/2) / Screen.height
正交：worldPerPixel = 2 * orthographicSize / Screen.height
```

#### 缩放

| 项 | 值 / 规则 |
|---|---|
| 触发 | 滚轮 |
| 输入 | `UI/ScrollWheel`（`<Mouse>/scroll`） |
| 每格距离 | `zoomStepPerNotch = 4` |
| 最近 | `minDistance = 20` |
| 最远 | `maxDistance = 100` |
| UI 屏蔽 | 指针在 UI 上时不缩放 |
| 滚轮归一化 | 绝对值 ≥ 1 时按符号算一格，兼容 ±1 / ±120 |

#### 输入动作共享的坑

`BuildingCameraController`、`BuildingPlacement`、`MiningInput` 共用同一批 InputAction。
`InputAction.Enable/Disable` **不是引用计数**：

- 本类 `OnDisable` 只重置状态，**不调用** `Disable()`。
- 控制期间每帧 `EnableAction()` 兜底，防止 `MiningInput` 被禁用时把共享动作一起关掉。
- `BuildingPlacement` 在 `LateUpdate` 里也有同样的兜底。

### 2.6 一帧内的执行顺序

```text
Update
  ├─ BuildingCameraDirector.Update：有蓝图 → EnterBuildMode；更新过渡插值
  ├─ AreaCameraDirector.Update：非建筑区 → SmoothDamp 到目标；建造模式/过渡 → 让位
  └─ BuildingCameraController 不在这里写相机

LateUpdate
  ├─ BuildingCameraController：建造模式且不在过渡 → 平移 / 缩放
  ├─ BuildingPlacement：补开共享的确认动作
  ├─ BuildingManager：落实延后的挖矿恢复
  └─ GameAreaController：非挖矿区强制关闭 MiningInput
```

### 2.7 当前限制 / 风险

- **建筑 → 商店会绕路**：先回常规机位，再去商店（见 2.3）。
- **没有触屏操作**：当前只做桌面右键 + 滚轮；`Pointer` 读取已为触摸留口，但没有双指 / 单指手势。
- **没有旋转 / 环绕**：相机旋转固定，只平移与拉近拉远。
- **没有遮挡处理**：相机不会避让建筑或地形。
- **平移焦点不跨模式保存**：退出建造再进入会按当前相机重新求焦点，不会记住上次看到的位置。
- **`clampToGridBounds` 卡死边界**：想拍岛屿外围 / 海面时，必须关掉它或调大 `edgePadding`。
- **商店机位是推算值**：世界里还没有商店实体，摆好摊位后要用右键菜单重记。
- **重跑旧向导有覆盖风险**：阶段 3 向导会覆盖建造机位；阶段 7 向导不会。
- **多个相机**：三个脚本都按「手动指定 → 本物体 Camera → `Camera.main`」找相机，
  目前只有一台 Main Camera；多相机场景需要显式指定。

## 三、通用模块（规划提案）

> 以下四节全部是 **【提案】**，尚未写代码，也尚未拍板。每节都按
> 「现状 → 问题 → 建议 → 验收 → 不做什么」写，方便你逐条改。

### 3.0 共同原则

1. **不引入第三方框架**：不装 Zenject、UniRx、DOTween、Audio Toolkit 之类；用 Unity 自带能力。
2. **场景接线可见**：依赖优先 Inspector 引用或向导接线，不用运行时反射找服务。
3. **单一真相源**：金币在 `PlayerCurrency`、库存在 `MaterialInventory`、建筑在 `BuildingManager`；
   管理器只转发，不复制状态。
4. **事件只用于跨模块**：模块内部仍用 C# event；不为「统一」把每帧数据塞进事件总线。
5. **小步落地**：系统级工作最多 4 步，一步一确认；每步都能单独回滚。

### 3.1 全局事件系统

#### 现状

项目**没有**全局事件总线，跨模块通信靠「实例 C# event + Inspector 引用」。
现有事件清单（已核实）：

| 事件 | 发布者 | 当前订阅者 | 用途 |
|---|---|---|---|
| `OnMoneyChanged(int)` | `PlayerCurrency` | `CoinHudUI`、`ShopUI` | 金币显示 |
| `OnInventoryChanged()` | `MaterialInventory` | `ShopUI`、`BuildingMaterialPanel` | 库存显示 |
| `OnLevelChanged(int)` | `PlayerLevel` | `OreSpawner` | 等级驱动刷矿 |
| `OnAreaChanged(GameArea)` | `GameAreaController` | `AreaCameraDirector`、`BottomNavUI` | 区域切换 |
| `OnBlueprintClosed(bool)` | `BuildingManager` | `BuildingConstruction`、`PlayerLevel`、`SaveSystem` | 蓝图关闭 / 建成 |
| `OnBuildingRemoved(GameObject)` | `BuildingManager` | `SaveSystem` | 拆除后自动保存 |
| `OnConstructionChanged()` | `BuildingConstruction` | `BuildingMaterialPanel` | 刷新材料进度 |
| `OnMessage(string, bool)` | `BuildingConstruction` | `BuildingMaterialPanel` | 状态提示 |
| `OnDied(Ore)` | `Ore` | 矿石生成 / 掉落系统 | 矿石死亡 |
| `OnSaved()` / `OnLoaded()` | `SaveSystem` | 暂无 | 存读完成 |
| `OnCollected(int)` / `OnUnlocked(int,string)` | `CulturalFragmentDropper`（**static**） | 暂无 | 文化碎片 |

#### 问题

- UI 要显示某个数值，必须拿到发布者的实例引用；跨模块订阅靠 Inspector 一根根接线。
- `CulturalFragmentDropper` 是 **static event**，订阅者不退订就会跨场景泄漏。
- 没有统一日志，排查「谁没收到事件」只能读各脚本。
- 没有顺序保证；同一帧多个事件时，订阅者执行顺序取决于订阅顺序。

#### 【提案】最小可用的类型化 EventBus

放在 `Assets/Scripts/Core/Events/`，不替代现有实例事件，只服务**跨模块**场景：

```csharp
public static class EventBus
{
    public static void Subscribe<T>(Action<T> handler) where T : struct;
    public static void Unsubscribe<T>(Action<T> handler) where T : struct;
    public static void Publish<T>(T evt) where T : struct;
    public static int SubscriberCount<T>() where T : struct; // 调试用
}
```

事件定义用 `readonly struct`，例如：

| 事件结构 | 字段 | 替代 |
|---|---|---|
| `MoneyChanged` | `int Amount` | `PlayerCurrency.OnMoneyChanged`（迁移后） |
| `InventoryChanged` | 无 | `MaterialInventory.OnInventoryChanged` |
| `AreaChanged` | `GameArea Area` | `GameAreaController.OnAreaChanged` |
| `BuildingPlaced` | `BuildingData Data, RectInt Rect, IReadOnlyList<MaterialColor> Colors` | 新事件（供音频 / 任务 / 成就） |
| `BuildingRemoved` | `BuildingData Data` | 新事件 |
| `BlueprintClosed` | `bool Built` | 保留旧事件，逐步迁移 |
| `SaveCompleted` / `LoadCompleted` | 无 | `SaveSystem.OnSaved/OnLoaded` |

规则：

- **状态先提交，再发布**：例如金币先 `AddMoney`，再 `Publish`；订阅者读到的永远是已更新的值。
- **订阅在 `OnEnable`，退订在 `OnDisable` 或 `OnDestroy`**；禁止匿名 lambda 订阅（无法退订）。
- **每帧事件禁止**：指针移动、伤害跳字这类不进 EventBus。
- **Payload 不可变**：用 `readonly struct`，不传 `GameObject` 以外的可变集合（需要集合时传副本或只读接口）。
- **发布者不知道订阅者**；EventBus 内部对每个 handler 做 try/catch，单个订阅者抛异常不影响其他订阅者，但必须 `Debug.LogException`。
- **场景卸载时清空**：`EventBus.ClearAll()` 挂在场景切换 / `SaveSystem.Reset` 流程里，防止静态引用泄漏。

#### 迁移顺序（建议）

1. 新增 EventBus + 事件结构 + 单元级自测；**不迁移任何现有订阅者**。
2. 迁移 `AreaChanged`、`MoneyChanged`、`InventoryChanged` 三类「UI 只读」事件；
   旧 C# event 暂时保留，双发一段时间。
3. 迁移建筑相关事件；`PlayerLevel` 改订阅 `BuildingPlaced` / `BuildingRemoved`，
   顺手修 1.7 的「拆除不降级」。
4. 删除旧事件与双发代码；补 `SubscriberCount` 回归测试。

#### 验收

- [ ] 场景重载后 `SubscriberCount<T>() == 0`（没有静态泄漏）。
- [ ] 金币 / 库存 / 区域变化，UI 仍只刷新一次，不重复。
- [ ] 拆除建筑后等级正确下降。
- [ ] 单个订阅者抛异常，其他订阅者仍收到事件，Console 有完整堆栈。
- [ ] 关闭 EventBus 日志时无每帧 GC 分配（可用 Profiler 粗看）。

#### 不做什么

- 不做字符串 key 的 `Dictionary<string, object>` 总线。
- 不做「所有事件都走总线」；模块内部事件保留 C# event。
- 不做运行时反射自动订阅。

### 3.2 摄像机管理

#### 现状

三个脚本各自写相机，靠 `IsInBuildMode / IsTransitioning` 这两个公开属性做让位（见第二部分）。
目前只有「区域机位 + 建造机位」两类需求，**现有结构够用**。

#### 问题

- 归属规则是隐式的：新加一个「跟随矿石」「商店特写」「剧情运镜」时，很容易出现第四个写相机的人。
- 机位参数散落在三个组件上，没有统一的「机位集合」资产。
- 过渡中断、优先级、混合时长没有统一策略。

#### 【提案】什么时候才做 CameraManager

只有出现以下任一需求时再做，否则不要重写：

1. 新增第三种持续相机模式（跟随 / 环绕 / 第一人称）。
2. 需要同一时间多个请求竞争（剧情 > 建造 > 区域）。
3. 需要相机震动、景深、FOV 过渡等统一后处理。

建议结构：

```text
CameraManager（唯一写 Transform 的人）
  ├─ CameraMode: Area / Build / Follow / Cinematic
  ├─ Request(mode, pose, priority, blendTime)
  ├─ 优先级：Cinematic > Build > Follow > Area
  ├─ 同优先级：后请求覆盖先请求；释放后回退到栈顶
  └─ 所有 pose 来自 CameraPoseSet（ScriptableObject）或场景记录

AreaCameraDirector / BuildingCameraDirector / BuildingCameraController
  → 降级为「请求者」，不再直接写相机
```

规则：

- 过渡期间新请求：从**当前实际姿态**开始，不从上一次目标开始。
- 区域切换请求优先级低于建造；建造退出后自动回退到当前区域。
- 震动 / FOV 作为叠加层，不改变基础机位。
- 触屏手势放在 `CameraManager` 的输入层，不散落在各 director。

#### 现在就能做的小准备（低风险）

- 把「找相机」的三份重复代码抽成 `CameraResolver`（手动 → 自身 Camera → `Camera.main`）。
- 把机位记录逻辑抽成 `CameraPose` 结构 + 右键菜单，仍由现有脚本持有。
- 在 `BuildingCameraDirector` 补一个「请求退出到指定区域机位」的接口，
  解决 2.3 的「建筑 → 商店绕路」，但先不引入 Manager。

#### 验收

- [ ] 任意时刻只有一个脚本写相机（可在 `CameraManager` 里断言）。
- [ ] 建造模式退出后能直接回退到目标区域，不经过无关机位。
- [ ] 过渡被新请求打断时不跳变。
- [ ] 现有建造平移 / 缩放行为不变。

### 3.3 音频管理系统

#### 现状

- `Assets` 下**没有任何音频文件**（`.wav/.mp3/.ogg`），也没有 `AudioMixer`。
- `Assets/Scripts` 下**没有任何** `AudioSource` / `AudioClip` / `AudioManager` 代码。
- 也就是说：音频是从零开始，不存在迁移包袱。

#### 【提案】最小音频架构

```text
AudioManager（场景常驻，DontDestroyOnLoad 可选）
  ├─ AudioMixer：Master / Music / SFX / UI
  ├─ MusicSource（1 个，循环，淡入淡出）
  ├─ SfxPool（8–12 个 AudioSource，2D/3D 混用）
  └─ AudioCatalog（ScriptableObject：AudioId → Clip + 默认音量 + 是否 3D）

API：
  PlayMusic(AudioId id, float fadeSeconds = 1f)
  StopMusic(float fadeSeconds = 1f)
  PlaySfx(AudioId id, Vector3? position = null, float volumeScale = 1f)
  PlayUi(AudioId id)
  SetVolume(AudioChannel channel, float value)
```

`AudioId` 枚举**只能追加**，和 `GameArea` / `MaterialColor` 同一条约定。
`AudioCatalog` 负责把枚举解析成 Clip；找不到时明确报错，不静默。

#### 事件接线（依赖 3.1）

| 游戏事件 | 音效建议 | 空间 |
|---|---|---|
| 矿石受击 | 石头敲击，随机音高 ±5% | 3D，矿石位置 |
| 矿石碎裂 | 碎裂 + 奖励提示 | 3D |
| 金币增加 | 轻提示音，带冷却（≥ 0.1 秒） | 2D |
| 购买成功 / 失败 | 收银 / 错误 | UI |
| 进入建筑区 | 建造模式环境音或 BGM 切换 | 2D |
| 蓝图落位 | 木桩 / 确认音 | 2D |
| 材料放入 | 短促放置音 | 2D |
| 建造成功 | 建筑弹出音，与 `BuildingSpawnPop` 对齐 | 3D |
| 按钮点击 | 统一 UI 点击音 | UI |

#### 规则

- **不在每次播放时 `AddComponent<AudioSource>`**；用池。
- 同一音效设最小间隔（例如金币 0.1 秒），防止连击刷屏。
- 3D 音效距离衰减用 `AudioSource.rolloffMode`，不要每个调用方自己算音量。
- 音量设置**建议存 PlayerPrefs**，不要塞进 `SaveData`：
  存档重置 / 版本升级不该把玩家音量清零。若你希望「跟着存档走」，再改。
- `AudioManager` 不订阅具体玩法脚本，只订阅 3.1 的全局事件。

#### 验收

- [ ] 连续点击 100 次只产生有限 AudioSource，不泄漏。
- [ ] BGM 切换有淡入淡出，不硬切。
- [ ] 3D 音效随相机距离衰减；UI 音效不受相机影响。
- [ ] 静音 / 音量设置在重启后保留。
- [ ] 缺 Clip 时 Console 明确报出 `AudioId`，不静默。

### 3.4 UI 管理系统

#### 现状（已核实）

| 物体 | 组件 | 显隐由谁管 | 订阅 |
|---|---|---|---|
| `Canvas/BuildingPanel` | `BuildingUI` + 3 按钮 | `GameAreaController.buildingAreaPanels` 数组 | 按钮 UnityEvent |
| `Canvas/ShopPanel` | `ShopUI` + `ShopItemUI` | `GameAreaController.shopAreaPanels` 数组 | 金币 / 库存事件 |
| `Canvas/材料面板` | `BuildingMaterialPanel` + `SlidingPanel` | **自己**每帧看 `BuildingManager.IsPlacing` | 建造 / 库存事件 |
| `Canvas/BottomNav` | `BottomNavUI` | 常驻 | 区域事件 |
| `Canvas/CoinHud` | `CoinHudUI` | 常驻 | 金币事件 |

Canvas：Screen Space Overlay，Scale With Screen Size，1920×1080，Match Width。
UI 文本统一旧版 `UnityEngine.UI.Text`，**不用 TextMeshPro**（项目规则 10）。

#### 问题

- 面板显隐有**三个 owner**：区域数组、材料面板自己、SlidingPanel。
- 「指针是否在 UI 上」的判定重复了三份：
  `MiningInput`、`BuildingPlacement`、`BuildingCameraController` 各写一遍 `EventSystem.RaycastAll`。
- 没有统一的面板栈 / 模态 / 关闭优先级；以后加设置、确认框、教程会各写一套。
- 面板之间靠 Inspector 引用，跨面板通信没有统一入口。

#### 【提案】UIManager + UIPanel，但分步做

**第 1 步（低风险，建议先做）：抽 `PointerOverUI` 服务**

```csharp
public static class PointerOverUI
{
    public static bool IsOverUI(Vector2? screenPosition = null); // 默认当前指针
    public static bool IsOverUIThisFrame();
}
```

替换三处重复实现，统一 `EventSystem.RaycastAll` 与「没有 EventSystem 只警告一次」的行为。
这一步不改任何面板结构，回归面最小。

**第 2 步：UIPanel 基类 + UIManager**

```text
UIPanel（MonoBehaviour）
  ├─ UIPanelId Id
  ├─ Show() / Hide() / Toggle()
  ├─ CanvasGroup 控制可见与交互
  └─ 可选：SlidingPanel 作为表现层

UIManager
  ├─ 面板注册表：UIPanelId → UIPanel
  ├─ Open(id) / Close(id) / CloseTop()
  ├─ 面板栈（模态 / 弹窗）
  ├─ 区域映射：GameArea → UIPanelId[]
  └─ 全局「是否有模态打开」给输入层查询
```

规则：

- **面板根物体不要被外部 `SetActive(false)`**；统一走 `UIPanel.Hide()`。
- `材料面板` 继续由 `BuildingManager.IsPlacing` 驱动，但改为调 `UIManager.Open(MaterialPanel)`，
  不再自己每帧 `SetActive`。
- 常驻 HUD（金币、导航）不进面板栈，只注册为「常驻层」。
- 区域切换只改映射表，不逐个写 `SetActive`。
- 面板刷新优先订阅事件（3.1），不用 `Update` 轮询。

**第 3 步：模态与输入**

- `UIManager.HasModalOpen` → `MiningInput` / `BuildingPlacement` / 相机统一查询，替代各自判断。
- 模态打开时禁用世界点击与相机平移；关闭后恢复。
- `ESC` / 返回键统一由 `UIManager.CloseTop()` 处理（当前没有）。

#### 验收

- [ ] 三个区域来回切 20 次，面板显隐正确，没有面板卡在屏幕外。
- [ ] 材料面板滑出 / 滑回正常，导航条不被遮挡。
- [ ] 指针在 UI 上时，挖矿、建造落位、相机平移都不响应。
- [ ] 模态打开时世界输入被挡住；关闭后恢复。
- [ ] 场景重载后面板注册表为空且能重新注册，无重复面板。

#### 不做什么

- 不引入 UI 框架 / MVVM / 数据绑定库。
- 不把每个按钮都包一层命令对象。
- 不重做现有面板视觉。

### 3.5 模块关系（目标形态）

```text
                        ┌──────────────┐
                        │  EventBus    │
                        └──────┬───────┘
          ┌──────────────┬─────┴──────┬──────────────┐
          ▼              ▼            ▼              ▼
     UIManager      AudioManager  CameraManager   SaveSystem
          │              │            │              │
          ▼              ▼            ▼              ▼
     UIPanel 们       AudioPool    Camera 请求     参与者
          ▲                                          │
          └────────────── 玩法系统 ──────────────────┘
                 （Mining / Shop / Building）
```

- 玩法系统只发布事件，不反向依赖 UI / 音频 / 相机。
- 管理器只读状态、转发请求，不复制玩法数值。
- 存档仍走 `SaveParticipant`，不通过 EventBus 存数据。

### 3.6 落地顺序（建议，最多 4 步）

| 步骤 | 范围 | 主要文件 | 验收 | 风险 |

| 2 | 迁移区域 / 金币 / 库存事件 + UIManager 面板注册（先接区域面板） | `GameAreaController`、`CoinHudUI`、`ShopUI`、`BuildingMaterialPanel`、新增 `UIManager/UIPanel` | 3.1 + 3.4 第 2 步验收 | 中 |
| 3 | 建筑事件迁移 + 拆除降级修复 + 音频管理器（先接 3–5 个音效） | `BuildingManager`、`PlayerLevel`、新增 `Audio/*` | 3.1 + 3.3 验收 | 中 |

> 第 4 步不是必做项。只要还是「区域 + 建造」两类机位，现有三脚本结构更简单、更好查。
